================================================================================
INVESTIGATION - simple_python (the only non-environmental test failure)
================================================================================
Symptom: TEST_HTTP_INTEGRATION_REAL.test_http_bridge_sends_to_python_server
fails on assertion "response_message_id_matches"; the suite then aborts.

The Python test server DID answer (HTTP 200). What it answered, from
D:/prod/simple_python/logs/simple_python.log:

  {"type": "ERROR", "message_id": "unknown", "attributes":
   {"error_code": "INVALID_JSON",
    "error_message": "Invalid JSON received: Expecting property name enclosed
                      in double quotes: line 1 column 2 (char 1)"}}

So the request body Eiffel POSTED was malformed - broken after its opening
brace. HTTP_PYTHON_BRIDGE.send_message builds that body with
SIMPLE_JSON_OBJECT.as_json (src/http_python_bridge.e:154-155), which makes
simple_json 0.2.0 an immediate suspect. It is NOT the cause. Two independent
pieces of evidence:

(1) simple_json 0.2.0 emits VALID JSON for this exact message shape.
    A standalone probe (base + time + simple_json only, no simple_http, no
    simple_python) replicating PYTHON_MESSAGE.to_json field-for-field
    - put_string message_id / type / timestamp, put_object attributes - was
    compiled and run:

      BODY_BEGIN>>>{"message_id":"test_msg_001","type":"VALIDATION_REQUEST",
      "timestamp":"09/02/2026T1:10:41.244 PM","attributes":{}}<<<BODY_END
      LEN=113
      CHAR0=123 CHAR1=34

    Character 1 is 123 '{' and character 2 is 34 '"' - precisely the byte the
    Python decoder said was missing. The serializer is correct; the corruption
    happens after as_json returns, in transport.

(2) The transport is untested WIP, not today's work.
    simple_python builds against simple_http, and simple_http is checked out on
    wip/uncommitted-2026-09-02. That branch's single commit (223060d) is:

      "WIP found uncommitted on 2026-09-02: NET_HTTP_CLIENT -> CURL_HTTP_CLIENT
       backend switch (files dated 2026-02-12); untested, preserved on a branch"

    git diff main..HEAD is exactly the backend swap - simple_http.ecf trades
    net_http_client.ecf for curl_http_client.ecf, and src/simple_http.e retypes
    client, configure_session, execute_single_request and configure_redirects
    from NET_HTTP_CLIENT* to CURL_HTTP_CLIENT*. SIMPLE_HTTP.post now runs
    through a cURL session that has never been exercised against a real server.

    simple_http's own 15/15 suite passes because it does not POST a body to a
    live listener; simple_python's integration test is the first thing to do so.

Corroboration that this test used to pass, so the regression is real but older:
simple_python's tree is clean, TRANSPORT_STATUS.md line 32 records
"test_http_bridge_sends_to_python_server: OK", and commit 196a405 is titled
"all 34 tests passing".

CLASSIFICATION: PRE-EXISTING (WIP breakage in the simple_http dependency, dated
2026-02-12). NOT caused by simple_json 0.2.0 or by simple_datetime. The
timestamp field in this message comes from ISE's DATE_TIME
(src/python_message.e:43 - "timestamp: DATE_TIME"), not from simple_datetime, so
the noon-parse fix cannot reach it either.
ACTION: none taken. simple_python needs no adaptation. The item to raise with
Larry is whether the simple_http cURL backend swap should be finished or
reverted - that is a decision about simple_http's WIP branch, outside this
sweep's remit.
