SimpleChat — Hosting Guide

How to turn this PC into the chat room everybody else connects to.

You do not need to be a programmer to follow this. It takes about twenty minutes, most of which is waiting for a router page to load.

Hosting requires an administrator install. When Windows asks for permission as the installer starts, say yes. If you install “just for me” (a per-user install, with no elevation), the hosting option is not offered at all and only the chat window is installed — that is deliberate, not a fault. The server writes to a folder shared by the whole PC, registers a startup task for the whole PC, and puts the front-door program somewhere an ordinary account cannot rewrite it, which is part of what keeps it safe. None of that is possible without administrator rights.

If you already installed without elevating, just run the installer again, allow it, and tick the hosting box.

Do you even need this? No, if you only want to use the chat. Just open SimpleChat from the Start Menu, type the address your host gave you, and log in. This guide is only for the one person whose PC holds the room.

1. What is on this PC

WhatWhere
The programsC:\Program Files\SimpleChat
Your settingsC:\ProgramData\SimpleChat\server.toml
The room itself — accounts, messages, historyC:\ProgramData\SimpleChat\data\simple_chat.db
What the server printedC:\ProgramData\SimpleChat\server.log
The front door program (Caddy)C:\ProgramData\SimpleChat\caddy.exe
The front door's own logC:\ProgramData\SimpleChat\data\caddy.log
Your own chat window's settings%APPDATA%\simple_chat\client.toml
Uninstalling SimpleChat never deletes the room. The data folder, your server.toml and your backups all survive an uninstall, and survive an upgrade. If you truly want them gone you delete C:\ProgramData\SimpleChat yourself, on purpose.

That promise is SimpleChat's own uninstaller's. A third-party "cleaner" (Revo Uninstaller, IObit, CCleaner's uninstall and the like) does not keep it: their "leftovers" sweep finds the room folder and deletes it - accounts, every message, your settings and your backups - and asks nothing. Uninstall from Settings → Apps or the Start Menu, and run Back up the room first if the room matters.

2. First run — make yourself an account

The installer normally does this for you. When you finish an install with the hosting box ticked, three things happen in order, each waiting for the one before it:

  1. a console opens and asks you to create the first administrator (skipped if this PC already has a room);
  2. the server starts, and tells you whether it answered;
  3. the chat window opens, and you sign in with the account you just made.

You can untick any of those on the installer's last page and do them yourself. The rest of this section is how to do them by hand.

Before anyone can log in, the room needs its first administrator. There is no default account and no default password; you create the only one there will ever be, once.

  1. Start Menu → SimpleChat Server → Create first admin
  2. Type a username (letters, digits and underscore, up to 32 characters).
  3. Type a password twice when it asks.

Run it again later and it will simply say the room already has its first administrator, and change nothing. Use Create user for anybody else, and Reset a password for a member who has forgotten theirs.

The password is shown on screen as you type it — this version has no echo‑hiding on the console. It is never stored: what is kept is a PBKDF2 hash at 600,000 iterations.

If the server will not start, it is nearly always the port. The chat server ships on 8090 rather than 8080 because Apache, XAMPP, Tomcat and many development tools sit on 8080. If 8090 is taken too, the port is the one line to change — and it has to be changed in two files, to the same free number (anything from 1024 to 65535):
  1. C:\ProgramData\SimpleChat\server.toml → port = 8091  (“Edit server config”)
  2. %APPDATA%\simple_chat\client.toml → local_port = 8091

“Start server” checks first and, if the port is busy, names the program holding it instead of failing quietly into the log.

Then Start Menu → SimpleChat Server → Start server. It will tell you whether it came up. At this point the room works on this PC only — open SimpleChat and log in to prove it.

2a. Making accounts for your friends

Start Menu → SimpleChat Server → Create user, once per person.

There is no sign-up page, and that is deliberate. Nobody can create an account on your room but you. It asks for three things:

WhatRules
UsernameWhat they type to log in. 1–32 characters of a-z, 0-9 and underscore. No capitals, no spaces.
Display nameWhat the room shows beside their messages. Capitals, spaces and any language are fine — Hebrew, Greek, anything. Press Enter to just use the username.
PasswordTyped twice. It is visible on screen as you type; it is never stored, only a PBKDF2 hash at 600,000 iterations.

Then tell them their username, their password and the address of your room. They install SimpleChat, leave the hosting box unticked, and log in.

2b. When somebody forgets their password

Start Menu → SimpleChat Server → Reset a password. Type the username, then the new password twice. It does not ask for a display name — the account already has one, and this never renames anybody.

This includes you. If you are the only administrator and you have forgotten your own password, this is the way back in. Before it existed, the only remedy was to delete the room's database and lose every message in it.

Everyone signed in as that person is signed out by the reset, on every device. That is deliberate: if the password had been learned by somebody it should not have been, changing it would be worth nothing while their existing sign-in still worked. They log back in with the new password.

Stop the server first. “Create first admin”, “Create user” and “Reset a password” all open the database directly. They refuse to run while the server is up, because a write that races the running server's can fail on a database lock — the account would simply not be created, or, worse for a reset, the new password would never take effect while the old one went on working and nobody was signed out. Stop, do the job, start again.

2c. @claude — the AI member of the room

The installer offers a checkbox under “Hosting:”:

Add @claude to the room (uses this PC's Claude Code subscription; found on this PC: yes/no)

It starts ticked only if the installer can find a claude command on this PC. Ticked, it uncomments this block at the foot of C:\ProgramData\SimpleChat\server.toml — and you can uncomment it yourself at any time, which is exactly what you must do if you already had a server.toml, because the installer never edits a config you already have:

[[participants]]
handle = "@claude"
kind = "claude_code"
engine = "data/participants/claude"
bot_username = "claude_bot"
display_name = "Claude"
requests_per_hour = 5
max_characters = 1200
timeout_seconds = 120

@claude runs on this PC's own Claude Code subscription. The claude command has to be on the PATH of whichever account starts the server — which is not necessarily the account that installed it. If you tick “Start the chat server when Windows starts”, the server runs as whoever logs on, so claude must be on that person's PATH.

Nothing else has to be set up: the server creates the member claude_bot on first start, and a sandbox folder of its own under data\participants\claude. It answers up to five times an hour by default, in at most 1,200 characters.

3. Going public

Three things have to be true before a friend on the other side of town can reach you: a name, an open door on your router, and the front door program turned on.

3a. Get a name (DuckDNS)

Your home internet connection almost certainly does not have a fixed address, and it has no name at all. DuckDNS gives you both, free.

  1. Go to duckdns.org and sign in (Google, GitHub, etc.).
  2. Make up a name — say rixchat. Your address becomes rixchat.duckdns.org.
  3. Copy the token shown at the top of the page. It is a long string of letters and digits. Treat it like a password.

3b. Open the door on your router

Your router has to be told that when someone knocks from the internet, this PC answers. This is called port forwarding. Every router's screens differ, but the fields are always the same:

FieldWhat to put
External / public port443 (and 80 as well — Caddy needs it to obtain the certificate)
Internal / private portthe same, 443 (and 80)
Internal addressthis PC's address on your home network, e.g. 192.168.1.40
ProtocolTCP

To find this PC's address, open a Command Prompt and run ipconfig; you want the IPv4 Address line, usually starting 192.168. or 10.. Give this PC a fixed address in the router (often called “DHCP reservation”) so it does not change next month and quietly break everything.

Note that 443 is not 8080. The number in server.toml (port = 8090) is the door the chat server itself listens on, inside this PC. Caddy is what listens on 443 to the outside world and passes traffic inwards. You forward 443, not 8080. Leave 8080 alone.
CGNAT — the one thing that can stop you dead. Many internet providers (especially mobile broadband, Starlink, and a growing number of cable providers) no longer give each home its own public address. They put hundreds of homes behind one shared address. This is called carrier‑grade NAT, and if you are behind it no amount of port forwarding will work — the door you are opening is not the door the world knocks on.

How to tell: run ipconfig and look at your router's WAN address, or check your router's status page. If it starts with 100.64. through 100.127., or it does not match what icanhazip.com says, you are behind CGNAT. What to do: ring your provider and ask for a public IPv4 address — many will give you one free or for a small monthly fee. There is no software fix for this in SimpleChat.

3c. Turn the front door on

Start Menu → SimpleChat Server → Edit server config. You are changing two lines. Find this near the top:

front_door = "none"
# front_door = "caddy"
# public_name = "yourname.duckdns.org"

and make it this (delete the # marks, put your own name in):

front_door = "caddy"
public_name = "rixchat.duckdns.org"

Further down, find the [ddns] block and uncomment it so your name keeps pointing at your house when your provider changes your address:

[ddns]
enabled = true
provider = "duckdns"
domains = "rixchat"
token = "paste-your-duckdns-token-here"
interval_seconds = 300
Under domains put only the label — rixchat — not the whole rixchat.duckdns.org. This trips up nearly everyone once.

Save the file. Then Stop server and Start server again.

The first start after this takes a minute or so: Caddy is fetching a real HTTPS certificate for your name. You do not buy, copy or renew anything — that is entirely Caddy's business, and it renews itself from now on.

3d. Check it

From a phone, off your home wi-fi (use mobile data), open https://rixchat.duckdns.org/health in a browser. You should see a short line of text like {"store":true,"last_event_id":0}. That is the room answering from the outside world.

Now your friends install SimpleChat (leaving the hosting box unticked), put https://rixchat.duckdns.org in the Server box on the login window, and they are in.

4. Keeping it running

If you ticked Start the server when Windows starts during installation, Windows starts it for you at every logon and there is nothing to do. If you did not, you can add it later by running the installer again and ticking the box — or just use Start server in the Start Menu whenever you want the room up.

When something is not right, the answer is nearly always in the log: Start Menu → SimpleChat Server → Server log.

5. Backups

Start Menu → SimpleChat Server → Back up the room.

It stops nothing and asks nothing except that the server be stopped first — and it insists on that, because the database keeps recent messages in a companion file (simple_chat.db-wal) until it is closed. Copying a live database is how people lose the last hour of a conversation.

  1. Stop server
  2. Back up the room — it makes a dated folder under C:\ProgramData\SimpleChat\backups and opens it for you
  3. Start server

Send the whole folder, not just the one file.

6. A standby host — a friend who can take over

If your PC dies, or you go away for a fortnight and unplug it, the room goes with it. A standby host is a friend whose PC is set up and ready but switched off, so the room can come back within minutes instead of never.

Be clear about what this is. This is a cold standby, done by hand. The standby is as up to date as the last backup you sent and no more — anything said after that backup is lost when you fail over. Automatic replication between hosts, and the fencing that would stop two servers both believing they are in charge, are not implemented. They are the next feature. Until then the discipline below is what keeps the room in one piece, and it is a discipline, not a safety net.

Setting the standby up (once)

  1. Your friend installs SimpleChat with the hosting box ticked.
  2. They get their own DuckDNS name — e.g. rixchat-standby.duckdns.org — and their own token. Not yours.
  3. They set up their own port forward, exactly as in section 3b.
  4. They edit their server.toml with their own name, exactly as in section 3c.
  5. They leave the server STOPPED. They untick “start when Windows starts”, or run Stop server and leave it. Their PC is ready and silent.

Everyone's chat window learns both addresses

Every member (you included) opens %APPDATA%\simple_chat\client.toml and lists both, primary first (these two names are examples — put your own in):

server_urls = ["https://rixchat.duckdns.org", "https://rixchat-standby.duckdns.org"]

Nobody has to do anything on the day. The chat window tries each address in turn at startup and the first one that answers as a real SimpleChat server wins. If the primary is down and the standby is up, the window simply finds the standby. Leave the standby in the list permanently; an address that is not answering costs one short probe.

Keeping the standby fed

Every week or so — whatever you can keep up — you: Stop server, Back up the room, Start server, and send your friend the folder. They put it in place with Restore from backup and go back to doing nothing. That is the whole routine.

On the day it fails over

  1. Your friend runs Restore from backup with the newest folder you sent, if they have not already.
  2. They run Start server.
  3. Everyone's chat window finds them on its own, at the next restart. The room resumes from the last backup — anything said after it is gone.
THE ONE RULE. Only one server runs at a time.

When you come back, do not start your server again. Your copy of the room is now the old one, and everything your friends said while you were away is on your friend's PC, not yours. Until you have restored from a backup they send you, you are a client only — you use the chat like everybody else, pointed at their address.

To hand it back: your friend stops their server and sends you a backup; you restore it and start yours; they stay stopped. If you both run a server at once you get two rooms drifting apart, and there is nothing that merges them back together.

7. If something goes wrong

What you seeWhat it usually is
“The server did not answer” when startingRead Server log. Most often a typo in server.toml — the server names the exact field it refused.
Works at home, not from a phone on mobile dataPort forwarding or CGNAT. See 3b.
The certificate never arrivesPort 80 is not forwarded. Caddy needs it even though the chat runs on 443.
Friends could connect, now they cannotYour address changed and DDNS is off or the token is wrong. Check the [ddns] block.
The robot in messages is an empty boxThe emoji artwork did not install. Re-run the installer.
The chat window will not start at allcairo.dll is missing from the program folder. Re-run the installer.
